# WIKI.md — 韓國交換 LLM Wiki 規則

這份規則寫給維護這個 Wiki 的 AI。主題：**到韓國交換：從錄取到抵達**，讀者是完全沒準備過交換的同學。

## 結構

```
llm-wiki/
├─ WIKI.md        ← 本檔：規則
├─ raw/           ← 原始資料摘要（一份來源一檔，只讀，不改）
├─ wiki/          ← AI 維護的知識頁
│  ├─ index.md    ← 目錄：每頁一行摘要
│  ├─ log.md      ← 每次 ingest／討論／lint 的紀錄（只能往後加）
│  ├─ sources.md  ← 來源清單與可信度等級
│  ├─ conflicts.md← 來源互相矛盾或缺資料的地方
│  └─ <主題>.md   ← 主題頁
└─ pipeline/      ← 產生簡報的流程與檢查腳本
```

## Ingest 流程：先討論、後生成

1. 把新來源的重點摘要存成 `raw/sN-<slug>.md`，front matter 要有 id、url、publisher、tier、fetched。
2. **先跟使用者討論**：列出打算寫進 Wiki 的重點、發現的衝突和缺口，等使用者決定重點與處理方式。
3. 討論完才更新 `wiki/` 主題頁，並在 `log.md` 記下這次的決定。

## 寫作規則

- 每一個事實句結尾都要標來源，例如 `[S2]`；多個來源寫 `[S1][S2]`。
- 來源等級：`official`（學校、政府）優先；`secondary`（S6 這類民間資料）**只能用來描述流程概念**，不能當作文件清單、金額、天數、截止日的依據。
- 來源互相矛盾時，**兩個都寫並標出來源**，同時登記到 `conflicts.md`，不能自己選一個。
- 數字（天數、金額、日期）一律照來源原樣，不換算、不四捨五入；換算成台幣等需求要另外標「換算」。
- 專有名詞第一次出現時用白話解釋，例如「外國人登錄證（ARC，在韓國的身分證）」。
- 查不到的資訊寫「待確認」，並寫出應該去哪裡查。

## Lint（每次更新後執行）

執行 `python3 pipeline/check.py wiki`，檢查：每個事實句有沒有來源標記、引用的來源存不存在、secondary 來源有沒有被拿來支撐數字。
